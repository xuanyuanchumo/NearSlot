## 2. 用例字段模板

| 字段 | 说明 |
|---|---|
| 用例 ID | NS-TC-<模块>-NNN（模块：APPT/AUTH/WAIT/RECON/CONTRACT/INT） |
| 关联 FR/SLO | 逐条列出，链接 SSOT |
| 类型 | 单元 / 集成 / E2E / 压测 / 契约 |
| 优先级 | P0–P3 |
| 前置条件 | 数据、账号、时段、开关 |
| 步骤 | 编号 1..n |
| 预期 | 具体错误码 / DB 状态 / trace 字段 |
| 实际 | 执行后填写；与预期差异记入 BUG |
| 结果 | 通过 / 失败 / 阻塞 / 未执行 |

## 3. 样例用例清单（8 条）

| 用例 ID | 用例名 | 关联 FR/SLO | 类型 | 优先级 | 预期（摘要） |
|---|---|---|---|---|---|
| NS-TC-APPT-001 | 并发 100 抢 1 余量 | FR-3.1 / SLO 超卖=0 | 压测 | P0 | 恰好 1 成功、99 失败（50101/50102），余量=0，对账 ABNORMAL=0；条件见 perf §5 |
| NS-TC-APPT-002 | 回补反转语义（ADR-005） | FR-3.3 / SLO 对账差异=0 | 集成 | P0 | 取消回补显式传方向，trace 写 RESTORE 且 beforeQty/afterQty 反转，对账一致 |
| NS-TC-APPT-003 | 一人一时段重复 | FR-3.1 / 50102 | 契约 | P0 | 同用户同 slotId 第二次提交返回 50102，DB 仅一条（uq_user_slot 兜底） |
| NS-TC-APPT-004 | 技师时间重叠 | FR-2.2/3.1 / 08 §3 | 集成 | P0 | 同一 technicianId 相邻重叠时段第二单被拒，ZSet 时间轴重叠检测命中 |
| NS-TC-AUTH-005 | Token 改密失效 422 | FR-1.4 / SLO Token 失效 100% / 40102 | E2E | P0 | 改密 bump version，旧 AT 在 ≤1 请求内失效返回 401 + X-Auth-Reason: superseded；并发刷新 422 自愈 |
| NS-TC-CONTRACT-006 | Lua 返回码单一枚举（防 09 §F.1） | 09 §F.1 / api/design.md §3 | 契约 | P0 | 抢约/预扣 Lua 只返回统一枚举（200/501/511 等），调用方口径一致；不存在 0/1/2 与 200 混判 |
| NS-TC-WAIT-007 | 候补 exactly-once | FR-3.2 / 08 §5 / 09b §1 | 集成 | P0 | slot.opened 多实例消费仅提升一次；offer 表 (slot_id,user_id) 唯一约束；重复通知被 300s 去重窗口吞掉 |
| NS-TC-RECON-008 | 对账在途保护窗口 | 09b §2 / ADR-008 | 集成 | P0 | 延迟=阈值+1s 的消息不被误回滚；>阈值+2s（MESSAGE_DELAY_TIME+2000ms）才回补；orderId≠traceId |

## 4. 样例用例详情（节选，格式示范）

| 用例 ID | 前置条件 | 步骤 | 预期 | 实际 | 结果 |
|---|---|---|---|---|---|
| NS-TC-CONTRACT-006 | Testcontainers-Redis 加载真实 Lua 脚本；枚举表取自 api/design.md §3 | 1. 直接执行预扣脚本 → 2. 断言返回码 ∈ 统一枚举 → 3. 用 Java 服务层同口径解析 | 返回码为单一枚举，服务层不出现 r!=0 与 SUCCESS(200) 并存矛盾（09 §F.1） | 待执行 | 未执行 |
| NS-TC-RECON-008 | 构造仅 DEDUCT、无 DB 日志、age=阈值+1s 的 trace 与另一条 age=阈值+3s | 1. 跑对账任务 → 2. 查两条 trace 处理 | +1s 保留不回补；+3s 回补一次并删 trace；两 ID 独立（09b §2/§5） | 待执行 | 未执行 |
