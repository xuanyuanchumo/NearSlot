## 2. 正文结构

| 章节 | 填写要求 |
|---|---|
| 测试目标 | 结论前置：本轮要验证的核心假设（超卖=0、Token 失效 100%、必测清单全过） |
| 测试策略 | 直接引用 [strategy.md](../../testing/strategy.md) §1 金字塔 70/20/10 与 §2 必测清单，不复制 |
| 测试范围 | 按 FR-1~5 逐模块列在测/不在测，不在测说明原因 |
| 覆盖率门禁 | 行覆盖 ≥80%、核心包 ≥85%，阈值来源 strategy.md §1 |
| 环境资源 | Testcontainers 统一 mysql/redis/rabbitmq；独立压测环境 + 影子库；Clock 注入 |
| 排期与里程碑 | 与 development-plan.md DCIVF 闭环对齐；每轮产出 [软件测试报告.md](软件测试报告.md) |
| 入口/出口准则 | 入口：G3 代码评审通过；出口：G4 必测清单全过 + 覆盖率门禁通过 |
| 风险与应对 | 外部环境集成测试 @Tag("integration") 排除登记；性能数字必带条件（perf §5） |
| 反哺机制 | 缺陷通用问题 → standards/ 或 ADR → check_docs.py 校验（review-system.md §4） |
