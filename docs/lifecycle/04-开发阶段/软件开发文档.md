## 2. 正文结构

### 2.1 DCIVF 五环执行记录（每任务必走）

| 环 | 动作（SSOT：development-plan.md §2） | 本任务产出工件 | 完成判据 | 证据链接 |
|---|---|---|---|---|
| D 设计落位 | ADR/设计拆成接口、表、Redis 键、返回码、状态机 | 契约草案（附编号） | 每约定有唯一 FR-x/ADR-x/API-x | 待填 |
| C 契约先行 | 先冻结 OpenAPI/Lua 枚举/DDL/RedisConstants | openapi.json / 枚举 / N_*.sql | 契约测试先写且为红 | 待填 |
| I 实现落地 | 骨架→能力→集成；代码+单测+中文注释同 PR | 代码 + 单测 | 编译绿、无占位符 | 待填 |
| V 验证闭环 | 单测→集成→契约→门禁逐级自动化 | JaCoCo / Testcontainers / NS-G{n}-NNN | 全绿才过，红回 I 环 | 待填 |
| F 反哺闭环 | 两次同类 blocker → 更新 standards/ 或新增 ADR | ADR/规范修订 | check_docs 校验通过 | 待填 |

### 2.2 统一开发工作流（development-plan.md §6）

| 步 | 动作 | 依据 |
|---|---|---|
| 1 | 认领任务，建分支 `<type>/<scope>-<desc>` | [git.md](../../standards/git.md) §2 |
| 2 | D 环：核对 ADR/设计，写契约草案 | development-plan.md §2 |
| 3 | C 环：先写契约测试（红）与常量/DDL/OpenAPI | development-plan.md §2 |
| 4 | I 环：实现 + 单测 + 中文注释 | [coding.md](../../standards/coding.md) |
| 5 | V 环：本地 mvn test → 集成(tag) → 契约 → 自检 | coding.md §5 |
| 6 | 提 PR：背景/变更/自检/测试证据/影响面 | git.md §3 |
| 7 | reviewer 预审（文件+行号+级别）→ 修复 → 人签 | [review-system.md](../../quality/review-system.md) §3 |
| 8 | F 环：两次同类 blocker → ADR/standards 反哺 | review-system.md §4 |
| 9 | 阶段末：出口门禁 + 复盘 | [roadmap.md](../../planning/roadmap.md) |

### 2.3 分支与提交规则（引用，不复制）

| 项 | 规则摘要 | SSOT |
|---|---|---|
| Commit 格式 | `<type>(<scope>): <subject>`，中文 ≤50 字祈使句、无句号 | [git.md](../../standards/git.md) §1 |
| type 枚举 | feat/fix/docs/style/refactor/perf/test/chore/ci/revert | git.md §1 |
| 分支命名 | `<type>/<scope>-<desc>`（kebab-case）；main 保护 + develop + feature/fix；hotfix 从 main 双向回 | git.md §2 |
| 合并方式 | Squash Merge 为主，禁 force push 共享分支 | git.md §2 |
| 版本握手 | Maven revision + flatten-maven-plugin；发布打 `v{semver}` tag | git.md §4 / [research/10](../../research/10-backend-engineering-deep.md) |

### 2.4 PR 描述字段（提交时逐项填）

| 字段 | 内容要求 | 依据 |
|---|---|---|
| 背景 | 关联任务号 NS-P{phase}-T{NN} 与 FR/ADR 编号 | git.md §3 |
| 变更点 | 文件+行号级说明；文档与代码同 PR | git.md §3 |
| 自检清单 | 下方 §3 全绿 | coding.md §5 |
| 测试证据 | 单测/集成/契约命令与结果；性能敏感变更附复测数据或声明无影响 | [performance/guide.md](../../performance/guide.md) §6 |
| 影响面 | 缓存键/Lua/SQL/线程池/配置变更声明；回滚方式 | git.md §3 / [deployment/guide.md](../../deployment/guide.md) §5 |

## 3. 检查单（Developer 提交前自检，对齐五维门禁）

| 维度 | 检查项 | SSOT | 结果 |
|---|---|---|---|
| 功能 | 契约先行；新增逻辑有单测；主链+边界（并发/重复/取消/超时） | development-plan.md §2/§4 | ☐ |
| 安全 | 无密钥硬编码；越权/注入按 security/guidelines 处理 | [security/guidelines.md](../../security/guidelines.md) | ☐ |
| 性能 | 缓存键与 TTL 在 RedisConstants/yaml 可查；Lua/SQL 变更有复测声明 | performance/guide.md §6 | ☐ |
| 可维护 | 中文注释齐（公共 API/复杂逻辑）；命名合规；check_docs.py 绿 | coding.md §1/§5 | ☐ |
| 可观测 | 日志级别恰当不刷屏；trace 白名单内埋点 | [quality-attributes.md](../../quality/quality-attributes.md) §3 | ☐ |
| 协作 | commit 合规；至少 1 名 Reviewer；ADR 变更附决策记录 | git.md §3 | ☐ |
