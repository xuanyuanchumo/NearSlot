## 2. 正文结构

### 2.1 中文注释规则（SSOT：coding.md §1）

| 对象 | 规则 | 本任务落实情况 |
|---|---|---|
| 公共 API / 复杂逻辑 | 中文 Javadoc，说明「为什么」而非「是什么」 | 待填 |
| 类头 | 注明来源项目参考（如「参考 PickNear TokenService」） | 待填 |
| 命名 | 类 UpperCamel；方法/变量 lowerCamel；常量 UPPER_SNAKE；包名单层小写语义 | 待填 |
| 规模 | 方法 ≤60 行、类 ≤400 行、圈复杂度 ≤10，超出拆策略/提类 | 待填 |
| 异常 | BizException(code) 统一；禁吞异常（catch 必 log.warn 带 context 或重抛） | 待填 |

### 2.2 返回码枚举单一来源（SSOT：research/10 §1 + coding.md §2）

| 规则 | 说明 | 依据 |
|---|---|---|
| 单一枚举 | `BaseCode`（Java 侧）+ `SeckillOrderCode` 模式（Lua 语义侧）为唯一来源，码→枚举→异常→日志一条链 | research/10 §1 |
| 禁魔法数字 | Lua 返回 code 必须有枚举映射，禁止裸数字透传与 JSON 码双口径 | coding.md §2 |
| 契约测试 | 返回码变更必须同步契约测试（红→绿），防 0/1/2 与 200/501 双口径重现 | research/09 §F.1 |
| 前端对齐 | 统一响应体 `{code,message,data,timestamp}`；前端按 code 文案分支 | [api/design.md](../../api/design.md) |

### 2.3 Lua / Java 共享返回码表（填写时逐码对齐）

| 场景 | Java 枚举（单一源） | Lua 返回码 | 对外 HTTP 码 | 契约测试编号 | 禁止做法 |
|---|---|---|---|---|---|
| 抢约成功 | 待填（如 SeckillOrderCode.OK） | 待填 | 待填 | 待填 | 直接返回裸 0 |
| 库存不足 | 待填 | 待填 | 待填 | 待填 | Lua 返回 1 / Java 映射 501 各写各的 |
| 重复抢约（去重） | 待填 | 待填 | 待填 | 待填 | 无枚举报文字符串判断 |
| Hold 超时 / 回补 | 待填 | 待填 | 待填 | 待填 | 魔法数字写死在 Lua 脚本 |
| Token 失效 422 自愈 | 待填（401xx/422） | 不经过 Lua | 422 | 待填 | 前端无限重试 |
| 限流 / 幂等 429 | 待填（429xx） | 待填 | 429 | 待填 | 无 X-Auth-Reason 分支 |

> 填写纪律：一行只能有一个权威码定义；Lua 与 Java 若出现不一致，回 C 环统一枚举并补契约测试，不得在本表并列两套真值。
