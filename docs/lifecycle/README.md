# NearSlot 项目生命周期文档目录（总索引）

> **来源**：整理自软件项目文档资料库截图（计划/需求/设计/开发/测试/验收六阶段 + 立项/项目计划/设计说明/编码实现/集成测试/产品交付六类 + 安全合规运维模板）。
> **核心原则**：本目录只承载**文档索引 + 模板骨架**；具体设计/需求/规范内容以 [docs](../README.md) 既有文档为唯一事实源（SSOT），模板通过相对链接引用，杜绝双源漂移。
> **使用方式**：随生命周期推进，在对应阶段目录复制模板 → 填内容 → 关联 FR/ADR → 过门禁；模板标「模板/待填」时不得当作已交付证据。

## 4. 模板通用规范（所有阶段目录适用）

每个模板必须包含：
1. **文档信息表**：编号 / 版本 / 状态(模板|待填|生效) / 责任代理(designer/developer/tester/reviewer) / 关联 FR 或 ADR / 关联既有文档（相对链接）。
2. **正文结构**：表格优先、结论前置；NearSlot 专属填写提示（时段预约/Hold/候补/对账/AI 双闸口）。
3. **检查单**：与门禁五维（功能/安全/性能/可维护/可观测）对齐。
4. **变更记录表**：版本 / 日期 / 变更人 / 说明 / 关联的 ADR 或 standards 反哺。

文档治理遵循 [standards/doc.md](../standards/doc.md)：frontmatter 必填、一主题一 current、历史靠 Git；确定性检查由 Phase 0 的 `check_docs.py` 覆盖。

## 5. 维护

- 新增模板先在本文档 §3 映射表登记，再建文件；门禁反哺产生的规范更新同步到对应模板检查单。
- 每阶段结束由 reviewer 核对：模板是否已填、是否与 SSOT 一致、是否有孤儿文档（无 FR/ADR 关联）。
