# 指导核心

> NearSlot/docs/ 的各文档为主 + hmdp-plus / PickNear 为辅助，及时参考和更新 NearSlot/docs/ 对应文档，利用其对项目的全周期各阶段进行指导。

## 执行要求（由上述原则展开）

1. **docs 为主**：动手前先查 `docs/` 对应章节（需求→quality/functional-requirements.md、设计→architecture/、接口→api/design.md、数据→database/schema.md、规范→standards/）。
2. **两项目为辅**：PickNear / hmdp-plus 仅作实现参考与纠错证据；引用时标注来源文件与行号。
3. **及时回写**：任何实现变更后，同步更新对应 docs（需求状态表、端点清单、ADR、踩坑记录），不留"代码已变、文档未变"。
4. **文档即门禁**：`check_docs.py` 四检 + `check-wheels.sh` 成熟库检查必须绿。
5. **成熟库优先：**有成熟库优先使用成熟库，非必要不进行造轮子。
6. 合理运用各种数据结构与算法和数学模型。
7. 数据、业务、需求、架构等各方面的能力连通性都根据研究文档进行落地闭环。
